## Mission

Create a **collective display** that combines:

1. The new **Incidents Atlas** (`data/incidents.json` → `incidents/`), and  
2. All **harness-published cybersecurity / exploit / CVE / CWE scores** already stored under `data/harnesses/`,

into one Atlas-style visual surface (same family as `index.html` stations and `models/*.html` profile pages). Emphasize **school districts, K–12, and higher education** from the incidents side, and keep **benchmark provenance** separate by harness on the scores side.

Do **not** average scores across harnesses. Do **not** invent incidents or scores.

## Why this handoff exists

Revision 1 of the Incidents Atlas is already built as a companion to the Frontier Model Matrix. It does not yet join the publisher cyber benchmarks into one collective board. Micah asked for a visual collection similar to the model-release pages; the next step is a **single combined display** that places real-world confirmed events beside the cyber capability cells the labs already published.

## Topic definition

**In scope for the collective display**

- Confirmed (or explicitly labeled researcher-reported) **sandbox escapes / evaluation egress / runaway agents** since 2026-01-01  
- Confirmed **K–12 / school-district and higher-ed** ransomware or data-theft breaches since 2026-01-01  
- Harness cells for **cyber / exploit / vulnerability** benchmarks already in this repo  

**Out of scope unless Micah expands the brief**

- Leak-site-only school claims without district confirmation (already omitted from `incidents.json`)  
- General coding benchmarks (Terminal-Bench, DeepSWE, etc.) except as optional side context  
- New offensive how-to content; this is a **documentation / observatory display**, not an exploit guide

## Suggested collective display shape

Match the Visual Atlas station pattern (hero + jump pills + sheets). Proposed stations:

1. **Education emphasis strip** — K–12 / higher-ed incident cards (already on `incidents/index.html`; reuse or deep-link)  
2. **Sandbox escape ↔ model map** — incident models linked to `models/<id>.html` and any cyber benchmark cells for that model  
3. **Cross-harness cyber matrix** — one expandable table per cyber `benchmarkId` (claim / rival / independent badges; never average)  
4. **Dual timeline** — incidents timeline beside a thin strip of cyber-model release dates that matter to the topic (Mythos, GPT-6 Cyber, Fable 5.2, etc.)  
5. **Method / provenance** — restate incidents confirmation rules + harness stance rules

- **C:** Cursor canvas companion for quick review, **in addition to** durable HTML in the repo (HTML remains source of truth for GitHub Pages / Atlas hub)

Keep dark mode, Archivo / Source Serif 4 / IBM Plex Mono, provenance badges, and the existing nav (add the new page to nav if it is a first-class surface).

## Provenance rules (do not break)

From the Frontier Model Matrix discipline:

- A number enters only through the harness that published it  
- Stance badges: claim / rival / independent  
- Origin badges: measured / quoted / derived / unspecified  
- Quoted and derived rows need notes  
- Blank means unpublished, not zero  
- Incidents: `confirmed` vs `researcher-reported`; do not upgrade status without a primary confirmation
